== Transfert vers le dépôt créé par l'utilisateur

Créer de préférence un dépôt distant vide, sans initialisation de README, licence ou fichier d'exclusion : l'historique local contient déjà ces fichiers.
Attendre l'adresse réelle ; ne pas inventer de dépôt ni créer une branche principale artificielle.
Une fois l'adresse reçue et la publication demandée, les commandes prévues depuis le dépôt Windows sont :

[source,powershell]
----
git remote add origin "URL_DU_DEPOT"
git push --set-upstream origin fonctionnalite/premiers-tests
----

`URL_DU_DEPOT` est une valeur à remplacer. Ne pas réexécuter `remote add` si le dépôt possède déjà un `origin` ; vérifier d'abord `git remote -v`.
Si le dépôt distant contient déjà un historique, l'inspecter et décider de son rapprochement ; ne pas forcer son remplacement.
Le choix de la branche par défaut distante reste à l'utilisateur.

Le transfert via Git contient sources, tests, documentation, licences et lanceurs Maven.
Il ne contient ni résultats `target`, ni journal privé, ni paramètres Git locaux, ni cache Maven, ni clé GPG, ni configuration du plugin.
Ne pas copier aveuglément tout le répertoire Windows pour reconstituer le dépôt Mac.

== Installation et vérification sur Mac

Installer un JDK 25. La référence de l'écosystème est Temurin 25 ; l'exécution déjà observée est sous OpenJDK 25.0.1 sur Windows.
Le fichier `.sdkmanrc` déclare `java=25-tem` et `maven=3.9.16` pour un poste utilisant SDKMAN.
Le lanceur Maven télécharge sa version 3.9.16 et les dépendances nécessaires ; aucune installation Maven globale n'est requise.

Après publication de la branche :

[source,shell]
----
git clone --branch fonctionnalite/premiers-tests "URL_DU_DEPOT" verne
cd verne

git config --local user.name "sidevconcept"
git config --local user.email "sidev.concept06@gmail.com"
git config --local commit.gpgsign false

printf '%s\n' '/PROMPTS.md' >> .git/info/exclude

java -version
./mvnw --version
./mvnw clean verify
----

Vérifier que Java annonce bien la version 25 avant la construction.
Si plusieurs JDK sont installés, le choix peut être explicité dans le terminal :

[source,shell]
----
export JAVA_HOME=$(/usr/libexec/java_home -v 25)
export PATH="$JAVA_HOME/bin:$PATH"
----

Le lanceur `mvnw` est versionné avec le mode exécutable `100755` et des fins de ligne LF ; le clonage doit suffire pour l'exécuter.
En cas de problème, vérifier `git ls-files --stage mvnw` et le montage du répertoire avant de modifier le projet.

L'exclusion locale `.git/info/exclude` ne voyage pas avec le dépôt : la recréer sur le Mac avant de commencer un nouveau `PROMPTS.md` local.
Ne pas transférer le journal Windows ; il reste sur son poste d'origine conformément à la consigne utilisateur.
La passation fournit le contexte nécessaire pour démarrer un journal Mac neuf.

Résultat attendu : 42 tests, zéro échec, zéro erreur et zéro test ignoré.
Une réussite sous Windows ne prouve pas encore cette réussite sur Mac : conserver le premier rapport Mac et documenter tout écart avant de continuer le développement.
Rapports : `verne-verification/target/surefire-reports`. Les journaux placés dans `target` sont supprimables par `clean` ; ne pas rediriger un journal ouvert vers ce répertoire pendant le nettoyage sous Windows.

Les commits suivants utilisent toujours :

[source,shell]
----
git commit -s -m "Décrire clairement le changement en français"
----

Le réglage `commit.gpgsign=false` est strictement local au clone ; ne pas désactiver globalement la signature des autres projets.
Si la signature est rétablie plus tard, configurer la vraie clé de l'utilisateur sur le poste puis ajuster explicitement cette règle.

== État effectivement livré

Le réacteur contient :

* `verne-compilation` : processeur `ProcesseurVerne`, analyse et génération `CompilateurGabarit`, module Java et déclaration de fournisseur.
* `verne-verification` : banc javac, exécution de vraies applications modulaires et suite JUnit. Une dépendance de test impose la construction préalable du compilateur.

Les gabarits UTF-8 `.verne` sont compilés dans la même invocation que les modèles Java sources.
Le profil livré est uniquement `texte`, avec paramètres obligatoires, interpolation de valeurs scalaires, navigation par composants de records, commentaires et échappements.
Les sources et classes Java sont générées au build ; les documents rendus ne demandent aucun JAR Verne à l'exécution.
L'intégralité des ressources déclarées est vérifiée, même lorsqu'un programme ne les appelle pas.

La taille d'une source est limitée à 1 048 576 octets, borne incluse.
Les constantes textuelles sont fractionnées sans couper une paire de substituts ; les caractères de contrôle et les littéraux Java sont protégés.
Les diagnostics sont français, avec codes stables et positions en points de code Unicode.
Les sources générées sont déterministes et sans chemin absolu.

Les détails normatifs et limites se trouvent dans link:docs/fr/modules/ROOT/pages/compilateur-minimal.adoc[le contrat du compilateur minimal].
Le profil texte ne protège pas une sortie HTML : aucun profil HTML sûr n'est encore livré.
