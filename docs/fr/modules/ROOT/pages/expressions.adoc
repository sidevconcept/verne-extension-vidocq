= Verne — Contrat des expressions
:lang: fr
:toc:

État : contrat proposé par le ticket VERNE-006 (nº 31), non implémenté. Il fixe la grammaire, la précédence, le typage, l'évaluation, les diagnostics et les limites des expressions avant toute implémentation. Le comportement livré reste celui du link:compilateur-minimal.adoc[contrat du compilateur] tant qu'un ticket d'implémentation n'a pas été intégré.

== Portée

Une expression peut apparaître à trois endroits : dans une interpolation (`{c.quantite * c.prix}`), dans la condition d'un bloc (`{#if c.total > 0 && !c.annulee}`) et, plus tard, dans les arguments de fonctions (F-11). La collection d'une boucle reste un chemin, sans opérateur : `{#for a in c.articles}`.

Ce contrat couvre les littéraux, les chemins existants, les opérateurs arithmétiques, de comparaison et logiques, les parenthèses, le typage, les conversions et la politique numérique.
Il exclut l'accès indexé (`liste[0]`), la navigation optionnelle et les valeurs de remplacement (F-07), les fonctions et espaces de noms (F-11), l'opérateur conditionnel ternaire, les affectations, la valeur `null` et toute évaluation Java arbitraire.

== Grammaire

Les espaces (espace, tabulation, fin de ligne) sont libres entre les éléments d'une expression et ignorés.

[source,ebnf]
----
expression     = ou ;
ou             = et , { "||" , et } ;
et             = egalite , { "&&" , egalite } ;
egalite        = comparaison , [ ( "==" | "!=" ) , comparaison ] ;
comparaison    = additif , [ ( "<" | "<=" | ">" | ">=" ) , additif ] ;
additif        = multiplicatif , { ( "+" | "-" ) , multiplicatif } ;
multiplicatif  = unaire , { ( "*" | "/" | "%" ) , unaire } ;
unaire         = ( "!" | "-" ) , unaire | primaire ;
primaire       = litteral | chemin | "(" , expression , ")" ;
chemin         = identifiant , { "." , identifiant } ;
litteral       = entier | decimal | chaine | "true" | "false" ;
entier         = ( "0" | chiffre-non-nul , { chiffre } ) , [ "L" ] ;
decimal        = ( "0" | chiffre-non-nul , { chiffre } ) , "." , chiffre , { chiffre } ;
chaine         = '"' , { caractere-de-chaine | "\" , ( '"' | "\" | "n" | "t" | "r" ) } , '"' ;
----

`identifiant` suit les règles actuelles des noms : identifiant Java non réservé, sans caractère ignoré. `true` et `false` sont des littéraux, jamais des chemins. `caractere-de-chaine` est tout caractère autre que le guillemet, l'antislash et une fin de ligne.

Les comparaisons et les égalités ne s'enchaînent pas : `a < b < c` et `a == b == c` sont refusés par `VERNE-SYN-002`. Des parenthèses rendent l'intention explicite : `(a == b) == c`.

Une directive se termine à la première accolade fermante située hors d'un littéral de chaîne : `{#if c.statut == "}"}` est une seule directive. Une chaîne non fermée produit `VERNE-SYN-001`, comme une directive non fermée.

=== Précédence

Du plus prioritaire au moins prioritaire ; les opérateurs d'une même ligne s'associent de gauche à droite, sauf mention contraire.

[cols="1,2,3",options="header"]
|===
|Rang |Opérateurs |Remarques
|1 |`( … )`, littéraux, chemins |
|2 |`!` `-` unaires |S'associent de droite à gauche : `!!a`, `- -a`
|3 |`*` `/` `%` |
|4 |`+` `-` |
|5 |`<` `<=` `>` `>=` |Non associatifs
|6 |`==` `!=` |Non associatifs
|7 |`&&` |Court-circuit
|8 |`\|\|` |Court-circuit
|===

=== Littéraux

* Un entier sans suffixe est un `int` ; il doit tenir dans `int`, sinon `VERNE-SYN-002`. Le suffixe `L` donne un `long`, qui doit tenir dans `long`. Les zéros de tête, séparateurs `_`, bases autres que décimale et exposants sont refusés. `-2147483648` s'écrit `-2147483648L` ou résulte d'un calcul : le littéral `2147483648` ne tient pas dans `int`.
* Un décimal est un `double` ; partie entière et partie décimale sont obligatoires (`0.5`, pas `.5` ni `5.`). Il est converti à la compilation vers le `double` le plus proche, arrondi au plus près comme `Double.parseDouble`. Le littéral est refusé par `VERNE-SYN-002`, à la compilation, si cette conversion donne une infinité, ou donne zéro alors qu'un de ses chiffres n'est pas nul. Un arrondi vers un autre `double` fini non nul est admis : `0.1` vaut le `double` le plus proche de 0,1, et une valeur sous-normale reste admise. Un littéral décimal ne peut donc introduire ni infinité ni `NaN` ; seules les opérations flottantes en produisent.
* Une chaîne est une `java.lang.String` ; seules les séquences `\"`, `\\`, `\n`, `\t` et `\r` sont admises.
* Un littéral est une valeur comme une autre : interpolé, il est échappé selon le profil, et il ne peut pas produire de balisage.

== Typage

Le typage est entièrement statique ; aucun type n'est découvert au rendu.

=== Catégories

[cols="1,3",options="header"]
|===
|Catégorie |Types
|Numérique |`byte`, `short`, `int`, `long`, `float`, `double` et leurs enveloppes ; `byte` et `short` sont promus en `int`
|Booléenne |`boolean`, `java.lang.Boolean`
|Caractère |`char`, `java.lang.Character`
|Chaîne |`java.lang.String`
|Autre |Tout autre type, record compris ; utilisable seulement comme départ de navigation
|===

Une enveloppe (`Integer`, `Boolean`…) se comporte comme son primitif ; elle est contrôlée non nulle au moment où sa valeur est utilisée, avec `VERNE-REN-001`.

=== Opérateurs

[cols="2,3,2",options="header"]
|===
|Opérateur |Opérandes admis |Résultat
|`+` `-` `*` `/` `%` binaires |Deux numériques |Type promu : `double` si l'un est `double`, sinon `float` si l'un est `float`, sinon `long` si l'un est `long`, sinon `int`
|`-` unaire |Un numérique |Type promu de l'opérande (`int` au moins)
|`<` `<=` `>` `>=` |Deux numériques, après promotion |`boolean`
|`==` `!=` |Deux numériques (après promotion), deux booléens, deux caractères ou deux chaînes |`boolean`
|`&&` `\|\|` |Deux booléens |`boolean`
|`!` |Un booléen |`boolean`
|===

Toute autre combinaison produit `VERNE-TYP-008` à la position de la directive, avec l'opérateur et les catégories en cause, sans valeur. En particulier :

* `+` avec une chaîne est refusé (D-006b) ; le message recommande de juxtaposer les interpolations ;
* un caractère n'est pas un nombre : `c.lettre + 1` est refusé ;
* les chaînes, booléens et caractères ne sont pas ordonnés : `c.nom < "m"` est refusé, l'ordre des chaînes dépendant de la langue ;
* deux records, ou un record et une chaîne, ne sont pas comparables.

L'égalité de deux chaînes compare leur contenu, jamais leur identité. Elle ne tolère pas `null` : chaque opérande chaîne, comme chaque enveloppe, est contrôlé non nul au moment où il est évalué, et une référence nulle lève `VERNE-REN-001`, que l'autre opérande soit nul ou non. Le résultat d'une égalité n'est donc jamais déduit d'une valeur nulle, conformément à F-07 (erreur par défaut) ; la comparaison explicite à une absence relèvera de la navigation optionnelle. L'égalité des flottants suit IEEE 754 : `NaN == NaN` est faux, `0.0 == -0.0` est vrai.

=== Usage du résultat

* Interpolation : le résultat doit être une chaîne, un primitif ou une enveloppe de primitif (D-006d) ; sinon `VERNE-TYP-004`. Une chaîne ou une enveloppe nulle lève `VERNE-REN-001`, comme aujourd'hui pour une chaîne : `String.valueOf` ne s'applique qu'à une valeur non nulle et ne produit jamais le texte `null`.
* Condition `{#if}` : le résultat doit être booléen, sinon `VERNE-TYP-006`. Aucune conversion implicite en booléen.
* Collection `{#for}` : reste un chemin ; une expression avec opérateur y produit `VERNE-SYN-002`.
* Profils : une chaîne ou un caractère est échappé comme aujourd'hui ; un résultat numérique ou booléen ne l'est pas. En JSON, un résultat chaîne ou caractère n'est admis que dans un littéral de chaîne, et un flottant non fini hors d'un littéral lève `VERNE-REN-003`, comme pour un chemin.

== Évaluation

* Les opérandes sont évalués de gauche à droite, chacun au plus une fois par occurrence dans l'expression. Un même chemin écrit deux fois est évalué deux fois : `{#if c.total > 0 && c.total < 100}` appelle deux fois l'accesseur `total`.
* `&&` n'évalue pas son opérande droit si le gauche est faux ; `||` ne l'évalue pas si le gauche est vrai. Un opérande non évalué ne peut lever aucune erreur.
* Chaque objet de navigation, chaque enveloppe et chaque chaîne opérande ou interpolée est contrôlé non nul au moment de son évaluation (`VERNE-REN-001`). Un opérande non évalué par court-circuit n'est pas contrôlé.
* Arithmétique entière (`int`, `long`) : addition, soustraction, multiplication, négation et division détectent le dépassement de capacité, y compris `Integer.MIN_VALUE / -1` ; la division et le reste par zéro sont également détectés. Dans ces cas, le rendu échoue par `ArithmeticException` portant `VERNE-REN-004`, sans valeur métier, et aucune sortie partielle n'est renvoyée (D-006e). La division entière tronque vers zéro et le reste prend le signe du dividende, comme en Java ; ce n'est pas un dépassement.
* Arithmétique flottante : IEEE 754, sans erreur ; une division par zéro donne une infinité ou `NaN`.
* Les expressions dont tous les opérandes sont des littéraux sont évaluées au rendu comme les autres ; leur éventuel dépassement est signalé au rendu.
* L'évaluation n'a aucun effet de bord propre et n'utilise que des variables locales : elle reste sûre en concurrence, comme le rendu actuel.

== Limites et budget

* Une expression compte au plus 64 opérateurs et 32 niveaux de parenthèses ; au-delà, `VERNE-LIM-010` à la position de la directive. La profondeur de chaque chemin reste bornée par `VERNE-LIM-005`.
* Budget pondéré de génération, en plus des 48 unités de la directive : 16 par accès de record (inchangé), 16 par chemin au-delà du premier, 24 par opérateur et 8 par littéral. Ces pondérations seront vérifiées sur le bytecode généré par le ticket d'implémentation, comme celles des blocs.

== Diagnostics

[cols="1,3",options="header"]
|===
|Code |Sens
|`VERNE-SYN-001` |Directive ou littéral de chaîne non fermé (sens étendu)
|`VERNE-SYN-002` |Expression mal formée, littéral invalide, comparaison ou égalité enchaînée, opérateur dans la collection d'une boucle (sens étendu)
|`VERNE-TYP-004` |Résultat d'interpolation qui n'est ni une chaîne, ni un primitif, ni une enveloppe de primitif (sens étendu)
|`VERNE-TYP-006` |Condition non booléenne (inchangé, s'applique aux expressions)
|`VERNE-TYP-008` |Opérande dont la catégorie est incompatible avec l'opérateur (nouveau)
|`VERNE-LIM-010` |Plus de 64 opérateurs ou de 32 niveaux de parenthèses dans une expression (nouveau)
|`VERNE-REN-001` |Objet de navigation, enveloppe ou chaîne nul évalué pendant le rendu (sens étendu)
|`VERNE-REN-004` |Dépassement de capacité entier, division ou reste entier par zéro (nouveau)
|===

Les diagnostics de compilation pointent le délimiteur ouvrant de la directive, comme aujourd'hui.

== Compatibilité et sécurité

* Tout gabarit valide aujourd'hui reste valide avec le même rendu : un chemin seul est une expression sans opérateur, et une enveloppe, auparavant refusée, ne pouvait pas apparaître dans un gabarit accepté.
* Les caractères `<`, `>` et `&` d'une expression appartiennent à la directive, pas au texte : ils ne participent pas à l'analyse des contextes HTML ou XML.
* Une expression ne peut appeler que les accesseurs de composants de records publics, comme un chemin ; aucune méthode, aucun champ, aucune classe n'est accessible.
* Une donnée n'est jamais analysée comme une expression.

== Cas de test

Les cas suivants détaillent T-EXP-01 et T-EXP-03 de link:cas-de-test.adoc[la liste des cas] pour ce contrat. Le modèle est `record Ligne(int quantite, long stock, double prix, Integer remise, boolean active, Boolean livree, String statut, String autre, char code, int zero, int minimum, int compteur, java.util.List<String> liste)`, déclaré par `{@exemple.Ligne l}`. L'accesseur `compteur` est redéfini pour compter ses appels dans un compteur de test indépendant.

=== T-EXP-01 — Précédence, parenthèses, comparaisons, négation et courts-circuits

[cols="3,3",options="header"]
|===
|Entrée |Sortie ou diagnostic attendu
|`{1 + 2 * 3}` |`7`
|`{(1 + 2) * 3}` |`9`
|`{10 - 4 - 3}` |`3` (associativité à gauche)
|`{-l.quantite * 2}` avec `quantite = 3` |`-6`
|`{7 / 2} {7 % 3} {-7 / 2} {-7 % 3}` |`3 1 -3 -1`
|`{l.quantite * l.prix}` avec `3` et `1.5` |`4.5` (promotion en `double`)
|`{l.quantite < l.stock}` avec `3` et `10L` |`true` (promotion en `long`)
|`{#if !l.active}A{#else}B{/if}` avec `active = true` |`B`
|`{#if l.active \|\| l.compteur > 0}` avec `active = true` |Branche rendue ; `compteur` jamais appelé
|`{#if !l.active && l.compteur > 0}` avec `active = true` |Branche non rendue ; `compteur` jamais appelé
|`{#if l.statut == "payé"}` avec `statut = new String("payé")` |Branche rendue (égalité de contenu)
|`{1 < 2 < 3}` |`VERNE-SYN-002`
|`{(1 < 2) == true}` |`true`
|`{#if l.quantite}` |`VERNE-TYP-006`
|`{l.statut + "x"}` |`VERNE-TYP-008`, message recommandant la juxtaposition
|`{l.code + 1}` |`VERNE-TYP-008`
|`{l.statut < "m"}` |`VERNE-TYP-008`
|`{#if l.statut == "}"}x{/if}` |Une seule directive ; `x` rendu si `statut` vaut `}`
|`{#for a in l.liste && true}` |`VERNE-SYN-002`
|`{#if l.livree && l.active}` avec `livree = null` |`VERNE-REN-001`
|`{#if l.active && l.livree}` avec `active = false`, `livree = null` |Branche non rendue, aucune erreur
|`{#if l.statut == "payé"}` avec `statut = null` |`VERNE-REN-001` au rendu, aucune sortie
|`{#if "payé" != l.statut}` avec `statut = null` |`VERNE-REN-001` au rendu (opérande droit évalué)
|`{#if l.statut == l.autre}` avec `statut = null` et `autre = null` |`VERNE-REN-001` au rendu ; deux nuls ne sont pas égaux
|`{#if l.active && l.statut == "x"}` avec `active = false`, `statut = null` |Branche non rendue, aucune erreur (opérande non évalué)

=== Autres cas de la famille
