= Verne — Gabarits textuels compilés
:lang: fr

*Moteur de gabarits textuels pour Java 25*, autonome et destiné à l'écosystème https://codefloe.com/Vidocq[Vidocq].
Les gabarits sont vérifiés et transformés en classes Java pendant la construction de l'application.
Le rendu utilise ensuite ces classes, sans analyse des gabarits à l'exécution.

[quote]
____
Verne rend hommage à *Jules Verne* (1828–1905), dont les récits associent imagination et précision. Le projet prépare les documents avant leur mise en mouvement : vérifier et compiler une fois, puis rendre à la demande.
____

== Principes

* *Aucune dépendance tierce à l'exécution* : les classes générées n'exigent que le JDK. Les bibliothèques de vérification restent en portée test.
* *Java 25 et Java Modules explicites* : chaque module possède son `module-info.java` ; les applications du banc sont exécutées sur le chemin des modules.
* *Validation pendant la construction* : tous les gabarits déclarés sont vérifiés, y compris ceux que l'application n'appelle pas.
* *Accès typés et directs* : les modèles sont résolus par le compilateur Java, sans réflexion métier ni balayage du chemin des classes.
* *Développement piloté par les tests* : contrat documenté, test observé en échec, implémentation minimale, puis vérification des régressions.

== Fonctionnalités disponibles

* Gabarits `.verne` en UTF-8 strict ; texte Unicode, espaces et fins de ligne conservés.
* Paramètres obligatoires typés, interpolation de chaînes et de scalaires, navigation par composants de records publics.
* Commentaires et échappement des délimiteurs.
* Classes de rendu sans état partagé et sources générées déterministes, sans chemin machine ni horodatage.
* Découverte automatique du processeur par javac, sur le chemin des processeurs ou des modules processeurs, depuis un répertoire ou un JAR.
* Exemple Maven autonome : compilateur déclaré uniquement sur le chemin des processeurs et application modulaire sans dépendance Verne à l'exécution.
* Coexistence avec un processeur générant des modèles Java : reprise des gabarits lorsque leurs types deviennent disponibles aux tours suivants.
* Chargement conjoint vérifié avec un voisin contrôlé dans Maven, sur les chemins classique et modulaire, sans ajouter de processeur au JAR applicatif.
* Diagnostics français avec codes stables et positions source ; refus des collisions de casse et de normalisation Unicode.
* Contrôle des racines et liens symboliques ; refus des cibles externes et des liens de fichiers cassés.
* Bornes initiales : *1 mébioctet par source*, *1 024 gabarits par compilation* et *1 024 interpolations par gabarit*, bornes incluses.

Le profil livré est *texte*. Il conserve les caractères spéciaux et ne fournit pas de protection HTML.
Les règles précises, erreurs et limites sont décrites dans link:docs/fr/modules/ROOT/pages/compilateur-minimal.adoc[le contrat du compilateur].

== Modules

[cols="1,3",options="header"]
|===
|Module |Rôle
|`verne-compilation` |Processeur de compilation, analyse des gabarits, vérification des types et génération Java ; dépend uniquement des API standard du JDK.
|`verne-verification` |Banc de compilation de vraies applications modulaires, exécution du rendu et tests de diagnostics, limites et portabilité.
|===

Les classes générées appartiennent à l'application ; aucun JAR Verne n'est nécessaire pour les exécuter.
L'adaptation CDI/REST et l'extension Vidocq restent à réaliser.

== Prérequis

* *JDK 25*, avec Temurin comme référence du projet.
* *Maven 3.9.16*, fourni par le lanceur `mvnw` ; aucune installation Maven globale n'est requise.

Le fichier `.sdkmanrc` déclare les versions pour les postes utilisant SDKMAN (`sdk env`).
Le premier lancement du lanceur peut télécharger Maven et les dépendances de construction et de test.

== Construction et tests

Depuis la racine du dépôt, sous Linux ou macOS :

[source,shell]
----
java -version
./mvnw --version
./mvnw -ntp clean verify
----

Sous Windows :

[source,powershell]
----
java -version
.\mvnw.cmd --version
.\mvnw.cmd -ntp clean verify
----

La vérification complète reconstruit les modules, exécute les tests et produit les archives.
Pour relancer les tests sans nettoyage, utiliser `./mvnw test` ou `.\mvnw.cmd test`.
Les rapports Surefire sont disponibles dans `verne-verification/target/surefire-reports` ; les répertoires `target` restent exclus de Git.

== Premier exemple

Le gabarit `bonjour.verne` déclare le paramètre `nom` et compose le document :

[source,text]
----
{@java.lang.String nom}Bonjour {nom}
----

Après compilation du gabarit avec l'application, la classe générée s'utilise directement :

[source,java]
----
String document = io.vidocq.verne.genere.Bonjour.rendre("Léa");
----

La valeur de `document` est `Bonjour Léa`.
Un paramètre obligatoire nul provoque une erreur explicite ; les données interpolées ne sont jamais réinterprétées comme un gabarit.
Le link:docs/fr/modules/ROOT/pages/compilateur-minimal.adoc[contrat livré] décrit les options du processeur et la grammaire acceptée. L'link:docs/fr/modules/ROOT/pages/application-maven.adoc[application Maven consommatrice] fournit un exemple autonome et les commandes de construction et de lancement.

== État du projet

*Version de développement : `0.1.0-SNAPSHOT`.* Le sous-ensemble texte est implémenté.
La dernière vérification complète sur Mac réussit avec *140 tests, zéro échec, zéro erreur et zéro test ignoré*.
Les 42 tests initiaux ont également été exécutés sur Windows ; les 98 tests supplémentaires restent à qualifier sur Windows et Linux.

Les conditions, boucles, inclusions, profils de sortie sécurisés, rendu en flux et asynchronisme ne sont pas encore livrés.
L'intégration Vidocq et les reconstructions incrémentales restent à réaliser ou à qualifier.
Aucune performance n'est revendiquée sans mesures reproductibles.
Les prochaines priorités figurent dans link:docs/fr/modules/ROOT/pages/index.adoc[le dossier de conception].
